## 1. สรุปภาพรวม

ระบบ CPAMS เป็นเว็บสำหรับบริหารงานหลังการขาย ครอบคลุมลูกค้า โปรเจกต์ งานในโปรเจกต์ การส่งมอบ ใบรับประกัน สัญญา MA ใบแจ้งปัญหา (ticket) การติดตามโปรเจกต์ แบบสำรวจความพึงพอใจ รายงาน และการจัดการผู้ใช้/สิทธิ์

ตลอดช่วงนี้ frontend ได้พัฒนาจากต้นแบบที่ใช้ข้อมูล mock ไปเป็นระบบที่ต่อ API จริงทั้งหมด และมีการคุมสิทธิ์รายเมนู/รายปุ่ม

## 2. เทคโนโลยีที่ใช้

- **Angular 19** แบบ standalone component, signals, `input()`/`output()`, control flow ใหม่ (`@if`, `@for`, `@let`)
- **Angular Material / CDK 19** สำหรับตาราง ฟอร์ม dialog datepicker เมนู tooltip
- **Tailwind CSS 4** ใช้คู่กับ SCSS กลาง (`src/styles/_list-panel.scss`) ที่คุมหน้าตารางทั้งระบบ
- **TypeScript 5.7, RxJS 7.8**
- **ng-openapi-gen** (`npm run api:gen`) สร้าง API client จาก OpenAPI ของ backend
- **ตัวจัดการวันที่แบบไทย** `ThaiCeDateAdapter` แสดงชื่อเดือนภาษาไทยแต่ใช้ปี ค.ศ. ทั้งระบบ และรองรับการพิมพ์แบบ dd/mm/yyyy

## 4. บันทึกงานรายวัน

### สัปดาห์ที่ 1 — วางโครงระบบและเปลี่ยนจาก mock เป็น API จริง

**7 ก.ย. (จันทร์)**
- เริ่มโปรเจกต์: Angular frontend พร้อมข้อมูล mock มีระบบล็อกอิน บทบาท/ผู้ใช้ ลูกค้า โปรเจกต์ ใบแจ้งปัญหา และ datepicker แบบไทย
- หน้ารายละเอียดลูกค้าแสดงใบรับประกันและสัญญา MA
- แยก routing ของติดตามงาน การแจ้งเตือน และ audit log เป็นหน้าเฉพาะ
- ปรับตัวจัดการวันที่ไทยให้แปลง/แสดงผลได้ดีขึ้น และเพิ่ม badge แจ้งเตือนบนเมนู

**8 ก.ย. (อังคาร)**
- หน้าแรกแสดงสถิติจากข้อมูลจริงของ service และทำหน้าแบบสำรวจ/รายงาน
- ติดตั้ง Tailwind CSS และปรับ layout หลายหน้าให้สม่ำเสมอ
- เพิ่มช่องค้นหาในเกือบทุกหน้า: ติดตามงาน แบบสำรวจ audit log สัญญา MA ผู้ใช้ ใบรับประกัน บทบาท
- เพิ่มการเรียงตามระดับความสำคัญ (งาน/ใบแจ้งปัญหา) และตามสถานะ (โปรเจกต์)
- หน้าเอกสารพรีวิวไฟล์แต่ละเวอร์ชันได้
- เตรียมต่อ API จริง: ตั้งค่า production build, สคริปต์ `api:gen`, HTTP interceptor, ปรับ auth guard ให้ตรวจสิทธิ์ และล้าง storage ของ mock เก่า

**9 ก.ย. (พุธ) — วันที่มี commit มากที่สุด (15 commit)**
- เปลี่ยน base URL ไปยังเซิร์ฟเวอร์ API จริง
- เพิ่ม directive กรอกเงิน และ pipe แสดงสกุลเงินให้เหมือนกันทั้งระบบ
- ตรวจและจัดรูปแบบเบอร์โทรศัพท์ไทยในฟอร์มลูกค้าและผู้ใช้
- ปุ่มย้อนกลับใช้รูปแบบเดียวกันทุกหน้า
- ปรับ model และ service ของการส่งมอบ ใบรับประกัน เอกสาร ติดตามงาน และ MA ให้ตรงกับ API
- แทน date pipe เดิมด้วย `ThaiDatePipe` และเพิ่มช่องกรอกเวลาแบบไทย
- ใบแจ้งปัญหา: แก้ไขและลบได้ ตรวจสิทธิ์รายปุ่ม (มอบหมาย / แก้ไข / ปิด)
- เพิ่มหน้าโปรไฟล์ ปุ่มล็อกอินด่วนสำหรับนักพัฒนา ตัวโหลดระหว่างเริ่มแอป และตัวเลือก "จำฉันไว้"

**10 ก.ย. (พฤหัส)**
- ติดตามงาน: เพิ่มข้อมูลลูกค้าและสถานะเลยกำหนด
- หน้าลูกค้า: จัดรายชื่อผู้ติดต่อเป็นการ์ด และค้นหาผู้ติดต่อ/โปรเจกต์ได้
- หน้าเอกสาร: เลือกโปรเจกต์แบบพิมพ์ค้นหา (autocomplete)
- ปรับ model ของแบบสำรวจและคำตอบ
- ป้ายระดับความสำคัญเป็นภาษาไทย ("NORMAL" → "ปานกลาง") และใช้ badge แบบเดียวกันทุกหน้า
- เพิ่มกระดานงานของโปรเจกต์ และสรุปคะแนนแบบสำรวจ

**11 ก.ย. (ศุกร์)**
- หน้าโปรเจกต์: แสดงงานส่งมอบเป็นตารางพร้อมค้นหา
- ลูกค้า: ตัดสถานะ "PROSPECT" ออก และจัดฟอร์มใหม่
- MA: แสดงโควตาแยกรายการ เตือนสัญญาที่ยังเป็นร่าง และเพิ่มหน้าจัดการแผน MA
- ใบแจ้งปัญหา: ผูกกับสัญญา MA และเตือนใบที่ยังไม่ได้ผูก ปิดใบได้เฉพาะตอนสถานะ RESOLVED และมีรอบแก้ไขอย่างน้อย 1 รอบ และกำหนดเงื่อนไขการเปิดใบใหม่
- เพิ่มการแบ่งหน้าในหน้าลูกค้า เอกสาร และการแจ้งเตือน
- งานที่สถานะเสร็จแล้วกรอกชั่วโมงจริงแทนชั่วโมงประมาณ
- เพิ่มการลบสัญญา โปรเจกต์ และใบแจ้งปัญหา โดยรวมปุ่มไว้ในเมนู "จัดการ"
- เพิ่มหน้า "งานของฉัน" และหน้าลูกค้าแบบ 360 องศา
- การส่งมอบมีสถานะ "ส่งมอบงวดสุดท้าย" และออกใบรับประกันจากการส่งมอบได้

### สัปดาห์ที่ 2 — จัดเมนู ขั้นตอนการทำงาน และงานในโปรเจกต์

**12 ก.ย. (เสาร์)**
- จัดเมนูเป็น 3 ชั้น: งานหลัก / ข้อมูล / ตั้งค่า
- หน้าแรกใหม่: การ์ด "ต้องทำวันนี้" 4 ใบ (กดแล้วไปรายการที่กรองไว้) และย้าย "งานของฉัน" มาไว้ในหน้าแรก
- ปุ่มลัด "+ เปิดใบแจ้งปัญหา" และ "+ บันทึกการติดต่อ" ใช้ได้จากทุกหน้า ทำให้งานหลัก 5 อย่างจบได้ภายใน 3 คลิก
- ฟอร์มเปิดใบแจ้งปัญหา: ตัดช่องผู้รับผิดชอบออกตามที่พี่เลี้ยงบอก เลือกโปรเจกต์แล้วเติมลูกค้าให้เอง และเตือนให้ค้นใบเดิมก่อนเปิดใบใหม่
- รวมหน้าลูกค้า 360 เข้าเมนูลูกค้า
- ใบรับประกันอ้างถึงสัญญา MA ได้
- บันทึกการส่งมอบได้เฉพาะตอนโปรเจกต์กำลังดำเนินการ
- ล้างคำที่ห้ามใช้ทั้ง 11 หน้า เช่น "รายได้", "โครงการ", รหัสโมดูล M0–M12
- เขียนเอกสารขอ API จาก backend (`docs/be-requests.md`)

**13 ก.ย. (อาทิตย์)**
- สร้างโปรเจกต์แบบทีละขั้น (wizard) พร้อมตรวจแต่ละขั้น
- หน้าโปรเจกต์มี checklist ความพร้อมก่อนส่งมอบ
- ใบแจ้งปัญหา: เพิ่มสถานะ ASSIGNED, timeline เหตุการณ์ และการเปิดใบซ้ำ

**14 ก.ย. (จันทร์)**
- รหัสลูกค้า โปรเจกต์ และสัญญา MA ให้ backend สร้างเอง (ตัดช่องกรอกรหัสออก) และแสดงรหัสหลังบันทึก
- ผลการแก้ไขใบแจ้งปัญหามี "สำเร็จบางส่วน" และ "ไม่สำเร็จ"
- ย้าย layout หลายหน้าไปใช้ Tailwind และปรับสีธีม
- การ์ดมูลค่าตลอดอายุลูกค้า พร้อม tooltip คำอธิบาย

**15 ก.ย. (อังคาร)**
- งาน: แยกหน้าตามโหมด (ของฉัน / ยังไม่มีคนรับ / กำลังทำ / รอตรวจ / เลยกำหนด) และทำเมนูย่อยแบบพับได้
- ตารางทุกหน้าเรียงลำดับได้จากหัวคอลัมน์ (เขียนเป็น utility ใช้ร่วมกัน)
- เพิ่มการส่งงาน (แนบไฟล์) และการตรวจงาน
- ฟอร์มใบแจ้งปัญหาแสดงขอบเขตความคุ้มครองของประกันและ MA
- เลือกผู้รับผิดชอบได้เฉพาะคนที่มีความสามารถตรงกับงาน
- แสดงความคืบหน้าโปรเจกต์ และเลื่อนสถานะโปรเจกต์เองเมื่องานแรกเริ่ม
- ตรวจไม่ให้วันครบกำหนดของงานอยู่ก่อนวันเริ่ม

**17 ก.ย. (พฤหัส)**
- หน้าลูกค้า: การ์ดข้อมูลกดดูรายละเอียดได้ (เลขผู้เสียภาษี ที่อยู่ LINE Facebook)
- รายงานโปรเจกต์: ความคืบหน้า จำนวนใบแจ้งปัญหา การส่งมอบ และสัญญา MA
- เพิ่มหน้าสร้างใบแจ้งปัญหาแบบแยกหน้า และตัวเลือกไฟล์แบบใหม่

- ใบรับประกัน: แนบเอกสาร พิมพ์ใบรับประกัน และเอาการลบออก (ตามกติกา backend)
- หน้าตรวจงานใหม่: แนบไฟล์ตอนตรวจ และดูประวัติการส่งงานก่อนหน้าได้
- เมนูซ้ายแบบกลุ่มซ้อนที่พับได้ และตารางงานแสดงรหัสโปรเจกต์

**29 ก.ย. (อังคาร)**
- การแจ้งเตือนแบ่งหน้าแบบ cursor และเลื่อนโหลดต่อได้เรื่อย ๆ
- ปรับการนับ badge บนเมนู (งานเปิดค้าง คิว Support ฯลฯ) และรีเฟรช badge อัตโนมัติหลังเรียก API ที่เกี่ยวข้อง
- เพิ่ม avatar ผู้ใช้
- ปิดติดตามงานแล้วตั้งครั้งถัดไปต่อได้ทันที
- หน้าลูกค้ากรองใบแจ้งปัญหาตามโปรเจกต์ได้ และแสดงเลขใบ/ชื่อโปรเจกต์
- ฟอร์มติดตามงานเลือกลูกค้าก่อนแล้วค่อยเลือกโปรเจกต์

**30 ก.ย. (พุธ)**
- **แดชบอร์ดของฉัน:** หน้าใหม่ แสดงเฉพาะข้อมูลของผู้ใช้เอง พร้อมแผงตัวกรองที่จัดใหม่
- **ตารางที่จอ 1122px:** แก้ที่ต้นเหตุ คือ Material บังคับ `table-layout: auto` ทับค่ากลาง จึงออกแบบระบบซ่อนคอลัมน์ใหม่ด้วย container query ในไฟล์กลาง (`col-hide-600` … `col-hide-1400`, `.cell-fill`, `.data-table--own-cols`) แล้วใช้กับหน้าใบรับประกัน โปรเจกต์ ติดตามงาน ลูกค้า และแบบสำรวจ
- หน้าใบแจ้งปัญหา: สถานะอ่านจาก `ticket.status` คอลัมน์หัวข้อไม่หดจนอ่านไม่ได้ และคิว Admin มีคอลัมน์เลขใบ
- Audit log: เลือกช่วงวันที่แบบ dd/mm/yyyy และแสดงชื่อผู้ใช้แทนรหัส
- รายงาน: หมายเหตุแสดงครั้งเดียว และการ์ด "ปัญหาในคิว" แสดงตามสิทธิ์ `ticket.view`
- เมนู "กระดานงาน" อยู่ในกลุ่ม "งาน" และการ์ดหน้าแรกเปลี่ยนชื่อเป็น "ปัญหาค้างทั้งทีม"
- **ใบรับประกัน (ตามข้อตกลงกับพี่เลี้ยง):** เอาขั้น "ยืนยันประกัน" ที่เก็บใน sessionStorage ออกทั้งหมด ปุ่ม "ออกประกัน" เปิดฟอร์มทุกครั้ง ถ้าช่วงประกันซ้ำ backend ตอบ 409 พร้อมข้อความไทยซึ่งแสดงตรง ๆ และเพิ่มป้าย "ยังไม่แนบใบที่ลูกค้าเซ็น" (เมื่อ `attachmentCount === 0` และไม่ใช่ VOID) พร้อมปุ่มแนบสแกน
- **ไฟล์ของรอบแก้ไขใบแจ้งปัญหา:** อัปโหลดเข้ารอบนั้นอย่างเดียว (`TICKET_RESOLUTION`) ไม่ส่งเข้าเอกสารโปรเจกต์อีก ข้อความเป็น "แนบไว้กับรอบที่ N แล้ว X ไฟล์" และส่วนแนบไฟล์แสดงเฉพาะคนที่มีสิทธิ์ `file.upload`

**1 ต.ค. (พฤหัส)**
- ป้าย "ยังไม่แนบใบที่ลูกค้าเซ็น" ลงบรรทัดใหม่ใต้สถานะ (`.cell-stack`) ไม่ถูกเซลล์ตัดทิ้ง
- แก้ปุ่มจัดการที่ถูกตัดเหลือราว 24px: จำกัดกฎ `.row-actions` ไม่ให้โดน `<td>` และแก้หน้า "ใบของฉัน" ที่มีอาการเดียวกัน
- ตารางประกันในหน้าโปรเจกต์ซ่อนคอลัมน์รองตามความกว้าง เพื่อไม่ให้ล้นที่ 1122px

## 6. ข้อตกลงและกติกาที่ยึดในการพัฒนา

- แก้เฉพาะฝั่ง frontend ห้ามแตะ backend/API ห้ามสร้าง mock ทับ endpoint และห้ามเดาฟิลด์ที่ API ไม่ได้ระบุ
- ไม่ทำ e-sign ไม่ใช้ `location.reload()` และไม่รวมคิวใบแจ้งปัญหาเข้ากับงาน
- กั้นเมนูด้วย `permissions` หรือ `accountType` เท่านั้น ไม่ใช้ `roles`
- วันที่ใช้ปี ค.ศ. ทั้งระบบ
- แดชบอร์ดของฉันแสดงเฉพาะข้อมูลของตัวเอง ไม่มีส่วนประเมินผล ค่าเป็น `null` คือซ่อน และสีของแต่ละตัวชี้วัดคงที่
- กฎ responsive ของตาราง (`@container`) เขียนในไฟล์กลาง `_list-panel.scss` ที่เดียว ห้ามแก้รายหน้า และห้ามใช้ `overflow: hidden` เพื่อกลบปัญหา
- ใบรับประกันไม่มีขั้นยืนยันซ้อน (backend บันทึกเป็นกติกาแล้ว) และ FE ไม่ดักช่วงประกันซ้ำเอง
- ทดสอบด้วยข้อมูลลูกค้าตัวอย่างเท่านั้น รายการทดสอบขึ้นต้นด้วย `[ทดสอบ]` และลบทิ้งหลังทดสอบ
- ทุกการแก้ไขต้องให้ `npm run build` ผ่านก่อนส่ง

## 7. ปัญหาสำคัญที่เจอและวิธีแก้

| ปัญหา | สาเหตุ | วิธีแก้ |
|---|---|---|
| ตารางล้นแนวนอนที่จอ 1122px | `.mat-mdc-table` ของ Material ตั้ง `table-layout: auto` ทับค่า `fixed` ในไฟล์กลาง จึงคุมความกว้างคอลัมน์ไม่ได้ | ออกแบบใหม่ให้รองรับ auto layout: container query ซ่อนคอลัมน์ตามความกว้างของแผง ให้คอลัมน์หลักยืดเต็มที่ที่เหลือด้วย `.cell-fill` และให้คอลัมน์ปุ่มกว้างเท่าเนื้อหา |
| SCSS ของแดชบอร์ดเกินงบ 8kB | เพิ่มสไตล์แผงตัวกรองใหม่ | รวมกฎการ์ดที่ซ้ำกัน ใช้ segmented control ร่วมกัน และตัด animation ที่ไม่จำเป็น |
| ป้ายประกันในตารางมองไม่เห็น | เซลล์ตารางสูงตายตัว 1 บรรทัดและตัดส่วนเกินทิ้ง | เพิ่มคลาส `.cell-stack` ให้เซลล์ที่ต้องมี 2 บรรทัด |
| ปุ่มจัดการเหลือราว 24px | กฎ `.row-actions { display: inline-flex }` ไปโดน `<td>` ทำให้เซลล์เสียความเป็นเซลล์ตาราง | จำกัดเป็น `.row-actions:not(td, th)` และแก้ SCSS หน้าที่ซ้ำอาการ |
| ขั้นยืนยันประกันขัดกติกา | ใช้ sessionStorage จำลองการยืนยันซ้ำ | ลบทั้งหมด และใช้ `attachmentCount` จาก backend แสดงป้ายแทน |
| ไฟล์รอบแก้ไขไปอยู่ผิดที่ | เดิมส่งเข้าเอกสารโปรเจกต์ก่อน ถ้าไม่ได้จึงแนบกับรอบ | อัปโหลดเข้า `TICKET_RESOLUTION` ของรอบนั้นอย่างเดียว |
