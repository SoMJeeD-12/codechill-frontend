# สิ่งที่ต้องขอจาก Backend

รวมรายการที่หน้าจอออกแบบไว้แล้วแต่ API ปัจจุบันยังทำให้ไม่ได้
ทุกข้อในนี้ **ห้ามทำเหมือนใช้ได้จริงบนหน้าจอ** — ให้ซ่อน หรือติดป้าย "ตัวอย่าง" ชัดเจน

อัปเดตล่าสุด: 12 ก.ย. 2569 (รอบเตรียมเดโมจันทร์)

> **แก้ความเข้าใจผิดรอบก่อน**
> - ค้นภาษาไทยด้วย `?search=` **ใช้ได้ฝั่ง backend แล้ว** — ไม่ใช่ข้อค้าง BE · ปัญหาเดิมอยู่ที่ FE ที่ดึง 100 แถวมากรองเอง (แก้แล้ว)
> - เตือนโควตา MA ตอนเปิดใบ **ทำได้ด้วย API ที่มีอยู่แล้ว** (list by `projectId` + `/quota`) — ทำบน FE แล้ว

---

## 1. สถานะ "ส่งงานให้ผู้รับผิดชอบแล้ว"

**อยากได้อะไร:** สถานะใบแจ้งปัญหาที่บอกว่า *หัวหน้ามอบหมายแล้ว แต่ผู้รับผิดชอบยังไม่เริ่มทำ*

**ติดที่หน้าจอไหน:** หน้ารายละเอียดใบ / รายการใบ — กด `PATCH /api/tickets/:id/assign` แล้วสถานะยังเป็น `RECEIVED` เหมือนเดิม แยกไม่ออกระหว่าง "ยังไม่มีใครรับ" กับ "มอบหมายแล้วรอเริ่ม"

**ถ้าไม่มีจะเสียอะไร:** พนักงานมองคิวไม่ชัด หัวหน้าไม่รู้ว่าใบไหนรอเริ่มแก้

**ตอนนี้ (ตรวจ Swagger แล้ว):** `TicketStatus` มีแค่ `RECEIVED` · `IN_PROGRESS` · `RESOLVED` · `REOPENED` · `CLOSED` — **ยังไม่มี `ASSIGNED`**

**สถานะบนหน้าจอ:** ซ่อน — แสดงแค่สถานะจริงจาก API · **รอบนี้ห้ามทำ mock ASSIGNED**

---

## 2. หมวดหมู่ปัญหา (Ticket Category)

**อยากได้อะไร:** จัดกลุ่มใบแจ้งปัญหาเพื่อดูว่าปัญหาประเภทไหนเกิดบ่อย

**ติดที่หน้าจอไหน:** ฟอร์มเปิดใบ / ตัวกรองหน้ารายการใบ

**ถ้าไม่มีจะเสียอะไร:** สรุปแนวโน้มปัญหาไม่ได้ ต้องไล่อ่านหัวข้อทีละใบ

**ตอนนี้ (ตรวจ Swagger แล้ว):** `POST /api/tickets` ไม่มีฟิลด์หมวดหมู่ และไม่มี endpoint หมวดหมู่ — **ยังไม่มี**

**สถานะบนหน้าจอ:** ซ่อน · **รอบนี้ห้ามทำ**

---

## 3. เตือนโควตา MA ตอนเปิดใบแจ้งปัญหา — ✅ ทำแล้ว (FE)

**อยากได้อะไร:** ตอนเลือกโปรเจคในฟอร์มเปิดใบ เห็นโควตา MA ของรอบปัจจุบัน และเตือนเมื่อหมด

**ทำได้อย่างไร (API ที่มีอยู่แล้ว):**
1. `GET /api/ma-contracts?projectId=<id>` → หาสัญญาที่ `isCurrentlyActive === true`
2. `GET /api/ma-contracts/<contractId>/quota` → `{ quota, used, remaining, isExhausted, periodStart, periodEnd }`

**สถานะบนหน้าจอ:** แสดงใต้ช่องเลือกโปรเจค · ไม่มีสัญญา = ไม่แสดงอะไร (ห้ามโชว์ 0) · `isExhausted` = คำเตือน

---

## 4. ประกันผูกกับแผน MA

**อยากได้อะไร:** ออกประกันแล้วให้ระบบรู้ว่าประกันนี้ต่อเนื่องเป็นสัญญา MA แผนไหน

**ติดที่หน้าจอไหน:** ฟอร์มออกประกันจากแท็บส่งมอบ

**ถ้าไม่มีจะเสียอะไร:** ต้องสร้างสัญญา MA แยกมือ ไม่รู้ว่าประกันใบไหนโยงแผนไหน

**ตอนนี้ (ตรวจ Swagger แล้ว):** `POST /api/deliveries/:id/warranties` ไม่รับ `maPlanId` / `maContractId`

**สถานะบนหน้าจอ:** ซ่อน — ฟอร์มออกประกันกรอกแค่ระยะเวลา

---

## 5. รายงานรายโปรเจค

**อยากได้อะไร:** สรุปตัวเลขของโปรเจคเดียว (งาน ส่งมอบ ปัญหา ชั่วโมง)

**ติดที่หน้าจอไหน:** หน้ารายละเอียดโปรเจค — ส่วน「รายงานของโปรเจคนี้」

**ถ้าไม่มีจะเสียอะไร:** พี่เลี้ยง/หัวหน้าดูภาพรวมโปรเจคไม่ได้จากที่เดียว ต้องไล่แท็บเอง

**ตอนนี้ (ตรวจ Swagger แล้ว):** `/api/reports/*` สรุประดับบริษัท/ลูกค้า/ประเภท — **ยังไม่มี `projectId` / project-summary**

**สถานะบนหน้าจอ:** แสดงเท่าที่มีจากข้อมูลในหน้า (ความคืบหน้า · จำนวนใบ · ส่งมอบ · สัญญา MA) พร้อมข้อความว่ายังไม่มี API รวม

---

## 6. พิมพ์ใบยืนยันการแก้ไข

**อยากได้อะไร:** ปุ่มพิมพ์ใบสรุปการแก้ไขให้ลูกค้าเซ็นรับ

**ติดที่หน้าจอไหน:** หน้ารายละเอียดใบแจ้งปัญหา

**ถ้าไม่มีจะเสียอะไร:** ต้องคัดลอกข้อมูลไปทำเอกสารนอกระบบ

**ตอนนี้ (ตรวจ Swagger แล้ว):** มีแค่ `GET /api/ma-contracts/:id/print` — **ไม่มี** `GET /api/tickets/:id/print`

**สถานะบนหน้าจอ:** ซ่อน · **รอบนี้ห้ามทำ**

---

## 7. รหัสอัตโนมัติ (Auto-generate code)

**อยากได้อะไร:** เปิดใบ/สร้างโปรเจค/สร้างลูกค้าแล้วได้รหัสอัตโนมัติ เช่น `TK-2569-0001`

**ติดที่หน้าจอไหน:** ทุกตารางและหน้ารายละเอียดที่โชว์ `code` / `ticketNo` / `deliveryNo` / `contractNo`

**ถ้าไม่มีจะเสียอะไร:** ค้นหาและอ้างอิงด้วยรหัสลำบาก ต้องพึ่งชื่อ

**ตอนนี้ (ตรวจ Swagger แล้ว):** ฟิลด์เป็น `string | null` — ระบบยังไม่ออกรหัสเอง

**สถานะบนหน้าจอ:** คอลัมน์รหัสแสดงอยู่ · ค่าว่าง = `—` · **ไม่บังคับกรอก · รอบนี้ห้ามทำออกรหัสอัตโนมัติ**

---

## 8. Timeline วันที่รายรอบการแก้ไข

**อยากได้อะไร:** ไทม์ไลน์เหตุการณ์เต็มใบ — รับเรื่อง / มอบหมาย / เริ่มแก้ / ปิดรอบ

**ติดที่หน้าจอไหน:** หน้ารายละเอียดใบ (ใต้รายการรอบ)

**ถ้าไม่มีจะเสียอะไร:** ดูได้แค่รอบแก้ไขจาก `resolutions` ไม่รู้เวลามอบหมายและลำดับเหตุการณ์อื่น

**ตอนนี้ (ตรวจ Swagger แล้ว):** ไม่มี `GET /api/tickets/:id/timeline` · ไม่มี `assignedAt` ใน Ticket DTO

**สถานะบนหน้าจอ:** ทำได้บางส่วน — รายการรอบจาก `resolutions` เรียงใหม่→เก่า · คลิกกางรายละเอียด

---

## 9. ระบบแจ้งเตือน (กระดิ่ง)

**อยากได้อะไร:** กระดิ่งบนแถบบน — งานถูกมอบหมาย · ใบเลยกำหนด · ประกันใกล้หมด

**ติดที่หน้าจอไหน:** แถบบนทุกหน้า

**ถ้าไม่มีจะเสียอะไร:** พนักงานต้องเข้าเมนูเองเพื่อรู้ว่างานใหม่เข้ามา

**ตอนนี้ (ตรวจ Swagger แล้ว):** **ไม่มี endpoint notification**

**สถานะบนหน้าจอ:** **ถอดออกแล้ว** · งานวันนี้แสดงบนหน้าแรกจาก API จริง · **รอบนี้ห้ามทำกระดิ่ง**

---

## หมายเหตุเพิ่มเติม — ไม่ถึงขั้นบล็อกงาน แต่ทำให้หน้าจอดีขึ้นมาก

### ก. `GET /api/tasks` ไม่มีตัวกรอง `overdue`
มี `/api/tasks/overdue` แยกต่างหาก ซึ่งใช้ได้ แต่ถ้าเพิ่ม `?overdue=true` ใน `/api/tasks`
จะรวมกับตัวกรองอื่น (`assignedUserId` + `overdue`) ได้ในครั้งเดียว
ตอนนี้หน้าแรกต้องยิง 2 ครั้งแล้วมา intersect ฝั่ง client

### ข. `GET /api/customers` ไม่มี `projectCount`
หน้ารายการลูกค้าอยากโชว์ว่าลูกค้ารายนี้มีกี่โปรเจค
ตอนนี้ต้องยิง `/api/projects?customerId=` ทีละราย — ทำไม่ไหวในหน้ารายการ

### ค. `POST /api/communication-logs` ไม่มีตัวเลือกสร้างงานติดตามต่อ
ปิดงานติดตามแล้วถามว่า "บันทึกการติดต่อเลยไหม" ซึ่งทำได้ด้วย 2 คำสั่ง
ถ้ามี atomic endpoint เดียวจะกันกรณีคำสั่งที่สองพัง
