# สิ่งที่ต้องขอจาก Backend



รวมรายการที่หน้าจอออกแบบไว้แล้วแต่ API ปัจจุบันยังทำให้ไม่ได้

ทุกข้อในนี้ **ห้ามทำเหมือนใช้ได้จริงบนหน้าจอ** — ให้ซ่อน หรือติดป้าย "ตัวอย่าง" ชัดเจน



อัปเดตล่าสุด: 14 ก.ย. 2569



> **คำสั่งงาน Backend รอบนี้:** ดู [`docs/be-work-order.md`](./be-work-order.md)  
> (timeline · รายงานโปรเจค · พิมพ์ใบยืนยันแก้ไข · admin รีเซ็ตรหัส · ออกแบบไฟล์แนบ metadata — **ไม่รวม** R2 · LINE · เรื่องรอพี่เลี้ยง)

> **แก้ความเข้าใจผิดรอบก่อน**

> - ค้นภาษาไทยด้วย `?search=` **ใช้ได้ฝั่ง backend แล้ว** — ไม่ใช่ข้อค้าง BE · ปัญหาเดิมอยู่ที่ FE ที่ดึง 100 แถวมากรองเอง (แก้แล้ว)

> - เตือนโควตา MA ตอนเปิดใบ **ทำได้ด้วย API ที่มีอยู่แล้ว** (list by `projectId` + `/quota`) — ทำบน FE แล้ว · ข้อมูลตัวอย่างตอนนี้มีสัญญา ACTIVE + pranee มี `ma.view` แล้ว

> - ประกันผูกสัญญา MA (`maContractId`) **ทำบน FE แล้ว** (ข้อ 4 ปิด)

> - SuperAdmin ใช้รหัสคนละตัวจาก `Demo@1234` — 401 ด้วย Demo@1234 คือถูก ไม่ใช่บั๊ก · อย่าจดกลับมา

> **ยังค้างรอคำตอบพี่เลี้ยง:** สถานะ ASSIGNED · หมวดหมู่ปัญหา · โควตาหลายประเภท · กระดิ่งแจ้งเตือน · **ลบใบแจ้งปัญหา / โปรเจค / ประกัน / สัญญา MA (DELETE)**

> **พี่เลี้ยงยืนยันแล้ว:** รหัสลูกค้า / โปรเจค / ใบแจ้งปัญหา ออกอัตโนมัติทั้งหมด

> **สั่ง BE แล้ว (ไม่รอพี่เลี้ยง):** timeline · รายงานรายโปรเจค · พิมพ์ใบยืนยันแก้ไข · admin รีเซ็ตรหัสผ่าน · ออกแบบไฟล์แนบ metadata · **รหัสอัตโนมัติ**

> **FE mock ชั่วคราว (ป้าย「ตัวอย่าง」ชัด · sessionStorage · ไม่ส่งขึ้น API):** ASSIGNED + ปุ่ม「เริ่มงาน」 · หมวดหมู่ปัญหาบนฟอร์ม · timeline จากฟิลด์ที่มี — ใช้โชว์ภาพให้พี่เลี้ยงเท่านั้น อย่าสับสนว่า BE พร้อมแล้ว

## 1. สถานะ "ส่งงานให้ผู้รับผิดชอบแล้ว"



**อยากได้อะไร:** สถานะใบแจ้งปัญหาที่บอกว่า *หัวหน้ามอบหมายแล้ว แต่ผู้รับผิดชอบยังไม่เริ่มทำ*



**ติดที่หน้าจอไหน:** หน้ารายละเอียดใบ / รายการใบ — กด `PATCH /api/tickets/:id/assign` แล้วสถานะยังเป็น `RECEIVED` เหมือนเดิม แยกไม่ออกระหว่าง "ยังไม่มีใครรับ" กับ "มอบหมายแล้วรอเริ่ม"



**ถ้าไม่มีจะเสียอะไร:** พนักงานมองคิวไม่ชัด หัวหน้าไม่รู้ว่าใบไหนรอเริ่มแก้



**ตอนนี้ (ตรวจ Swagger แล้ว):** `TicketStatus` มีแค่ `RECEIVED` · `IN_PROGRESS` · `RESOLVED` · `REOPENED` · `CLOSED` — **ยังไม่มี `ASSIGNED`**



**สถานะบนหน้าจอ:** **ตัวอย่าง (FE mock)** — หลังมอบหมายโชว์「ส่งให้ผู้รับผิดชอบแล้ว」+ ปุ่ม「เริ่มงาน」ก่อนเข้า IN_PROGRESS จริง · ติดแบนเนอร์ตัวอย่าง · เก็บใน sessionStorage · **ยังไม่ใช่สถานะจาก API**



---



## 2. หมวดหมู่ปัญหา (Ticket Category)



**อยากได้อะไร:** จัดกลุ่มใบแจ้งปัญหาเพื่อดูว่าปัญหาประเภทไหนเกิดบ่อย



**ติดที่หน้าจอไหน:** ฟอร์มเปิดใบ / ตัวกรองหน้ารายการใบ



**ถ้าไม่มีจะเสียอะไร:** สรุปแนวโน้มปัญหาไม่ได้ ต้องไล่อ่านหัวข้อทีละใบ



**ตอนนี้ (ตรวจ Swagger แล้ว):** `POST /api/tickets` ไม่มีฟิลด์หมวดหมู่ และไม่มี endpoint หมวดหมู่ — **ยังไม่มี**



**สถานะบนหน้าจอ:** **ตัวอย่าง (FE mock)** — เลือกหมวดในฟอร์มเปิด/แก้ไขใบ · โชว์ชิปบนหน้ารายละเอียด · เก็บ sessionStorage เท่านั้น · **ยังไม่ส่งขึ้น API**



---



## 3. เตือนโควตา MA ตอนเปิดใบแจ้งปัญหา — ✅ ทำแล้ว (FE)



**อยากได้อะไร:** ตอนเลือกโปรเจคในฟอร์มเปิดใบ เห็นโควตา MA ของรอบปัจจุบัน และเตือนเมื่อหมด



**ทำได้อย่างไร (API ที่มีอยู่แล้ว):**

1. `GET /api/ma-contracts?projectId=<id>` → หาสัญญาที่ `isCurrentlyActive === true`

2. `GET /api/ma-contracts/<contractId>/quota` → `{ quota, used, remaining, isExhausted, periodStart, periodEnd }`



**สถานะบนหน้าจอ:** แสดงใต้ช่องเลือกโปรเจค · ไม่มีสัญญา = ไม่แสดงอะไร (ห้ามโชว์ 0) · `isExhausted` = คำเตือน



---



## 4. ประกันผูกกับสัญญา MA — ✅ ทำแล้ว (FE + BE)



**อยากได้อะไร:** ตอนออกประกัน อ้างอิงสัญญา MA ของโปรเจคเดียวกันได้ (ไม่บังคับ)  
เพื่อรู้ว่าประกันใบนี้มาคู่กับสัญญาไหน — **ห้ามคิดรวมโควตา/เงิน/สถานะกับประกัน**



**ทำได้อย่างไร (API พร้อมแล้ว):**
1. `GET /api/ma-contracts?projectId=<โปรเจคของใบส่งมอบ>` → ตัวเลือกในฟอร์ม
2. `POST /api/deliveries/:id/warranties` ส่ง `maContractId` ได้ (ไม่ใส่ก็ได้)
3. `PUT /api/warranties/:id` ส่ง `maContractId: null` เพื่อถอดการผูก · ไม่ส่งฟิลด์ = คงค่าเดิม
4. response มี `maContractId` + `maContract: { id, contractNo, status, planCode, planName }`



**สถานะบนหน้าจอ:** ฟอร์มออก/แก้ประกันมีช่อง「สัญญา MA ที่ผูกกับประกันนี้ (ถ้ามี)」  
รายการ/รายละเอียดแสดง「ผูก MA: &lt;ชื่อแผน&gt;」หรือ「ไม่ได้ผูก MA」

## 5. รายงานรายโปรเจค



**อยากได้อะไร:** สรุปตัวเลขของโปรเจคเดียว (งาน ส่งมอบ ปัญหา ชั่วโมง)



**ติดที่หน้าจอไหน:** หน้ารายละเอียดโปรเจค — ส่วน「รายงานของโปรเจคนี้」



**ถ้าไม่มีจะเสียอะไร:** พี่เลี้ยง/หัวหน้าดูภาพรวมโปรเจคไม่ได้จากที่เดียว ต้องไล่แท็บเอง



**ตอนนี้ (ตรวจ Swagger แล้ว):** `/api/reports/*` สรุประดับบริษัท/ลูกค้า/ประเภท — **ยังไม่มี `projectId` / project-summary**



**สถานะบนหน้าจอ:** แสดงเท่าที่มีจากข้อมูลในหน้า (ความคืบหน้า · จำนวนใบ · ส่งมอบ · สัญญา MA) พร้อมข้อความว่ายังไม่มี API รวม · **สั่ง BE แล้ว** → [`be-work-order.md`](./be-work-order.md) §2

## 6. พิมพ์ใบยืนยันการแก้ไข

**ติดที่หน้าจอไหน:** หน้ารายละเอียดใบแจ้งปัญหา



**ถ้าไม่มีจะเสียอะไร:** ต้องคัดลอกข้อมูลไปทำเอกสารนอกระบบ

**สถานะบนหน้าจอ:** ซ่อน · **สั่ง BE แล้ว** → [`be-work-order.md`](./be-work-order.md) §3 (คืน JSON ให้ FE พิมพ์ · ไม่สร้าง PDF)

## 7. รหัสอัตโนมัติ (Auto-generate code) — พี่เลี้ยงยืนยันแล้ว



**อยากได้อะไร:** เปิดใบ/สร้างโปรเจค/สร้างลูกค้าแล้วได้รหัสอัตโนมัติ เช่น `TK-2569-0001`



**ติดที่หน้าจอไหน:** ทุกตารางและหน้ารายละเอียดที่โชว์ `code` / `ticketNo`



**ถ้าไม่มีจะเสียอะไร:** ค้นหาและอ้างอิงด้วยรหัสลำบาก ต้องพึ่งชื่อ



**ตอนนี้:** พี่เลี้ยงยืนยันให้ระบบออกอัตโนมัติทั้งหมด · **สั่ง BE แล้ว** → [`be-work-order.md`](./be-work-order.md) §0



**สถานะบนหน้าจอ (FE):**

- ตัดช่องกรอกรหัสจากฟอร์มสร้าง/แก้ไขลูกค้า · โปรเจค · ใบแจ้งปัญหา
- หลังสร้างสำเร็จ แสดง `code` / `ticketNo` จาก response ใน snackbar
- แสดงรหัสในหน้ารายการและหน้ารายละเอียด
- ค้นหาด้วยรหัส (placeholder + `?search=`) — รอ BE คืนรหัสจริงตอนสร้าง

## 8. Timeline วันที่รายรอบการแก้ไข



**อยากได้อะไร:** ไทม์ไลน์เหตุการณ์เต็มใบ — รับเรื่อง / มอบหมาย / เริ่มแก้ / ปิดรอบ



**ติดที่หน้าจอไหน:** หน้ารายละเอียดใบ (ใต้รายการรอบ)



**ถ้าไม่มีจะเสียอะไร:** ดูได้แค่รอบแก้ไขจาก `resolutions` ไม่รู้เวลามอบหมายและลำดับเหตุการณ์อื่น



**ตอนนี้ (ตรวจ Swagger แล้ว):** ไม่มี `GET /api/tickets/:id/timeline` · ไม่มี `assignedAt` ใน Ticket DTO



**สถานะบนหน้าจอ:** **ตัวอย่าง (FE mock)** — สร้างลำดับจาก `reportedAt` / มอบหมายจำลอง / `resolutions` / `closedAt` · ติดป้ายตัวอย่าง · **ยังไม่ใช่ `GET …/timeline`** · **สั่ง BE แล้ว** → [`be-work-order.md`](./be-work-order.md) §1

## 9. ระบบแจ้งเตือน (กระดิ่ง)



**อยากได้อะไร:** กระดิ่งบนแถบบน — งานถูกมอบหมาย · ใบเลยกำหนด · ประกันใกล้หมด



**ติดที่หน้าจอไหน:** แถบบนทุกหน้า



**ถ้าไม่มีจะเสียอะไร:** พนักงานต้องเข้าเมนูเองเพื่อรู้ว่างานใหม่เข้ามา



**ตอนนี้ (ตรวจ Swagger แล้ว):** **ไม่มี endpoint notification**



**สถานะบนหน้าจอ:** **ถอดออกแล้ว** · งานวันนี้แสดงบนหน้าแรกจาก API จริง · **รอบนี้ห้ามทำกระดิ่ง**

## 10. ลบใบแจ้งปัญหา (DELETE)



**อยากได้อะไร:** ลบใบทดสอบ/ใบผิดพลาดออกจากคิวได้



**ติดที่หน้าจอไหน:** เมนูจัดการในหน้ารายการใบแจ้งปัญหา



**ถ้าไม่มีจะเสียอะไร:** ใบทดลองค้างในคิว · กดลบแล้วได้ error ตอนสาธิต



**ตอนนี้ (ตรวจ Swagger 13 ก.ย. 2569 ดึก):**  
`GET/PATCH /api/tickets/:id` มี · เส้นอื่นของใบมี assign / resolutions / reopen / close  
**ใน `/api/docs-json` ยังไม่มี DELETE /api/tickets/:id** (มีสิทธิ์ `ticket.delete` ในระบบสิทธิ์แล้ว)



**สถานะบนหน้าจอ:** ซ่อนปุ่มลบไว้ก่อน · รอ BE เพิ่ม endpoint



---



## 11. ลบโปรเจค (DELETE)



**อยากได้อะไร:** ลบโปรเจคทดสอบ/สร้างผิดออกจากรายการได้



**ติดที่หน้าจอไหน:** เมนูจัดการหน้ารายการโปรเจค · หน้ารายละเอียดโปรเจค



**ถ้าไม่มีจะเสียอะไร:** กดลบแล้วได้ `Cannot DELETE /api/projects/:id` ตอนสาธิต (Nest ไม่มี route)



**ตอนนี้ (ตรวจ Swagger 13 ก.ย. 2569 ดึก):**  
`GET/PUT /api/projects/:id` มี · **ไม่มี DELETE**  
(ลบงานย่อย `DELETE /api/projects/:projectId/tasks/:taskId` มีแล้ว)  
มีสิทธิ์ `project.delete` ในระบบสิทธิ์แล้ว แต่ยังไม่มี endpoint



**สถานะบนหน้าจอ:** ซ่อนปุ่มลบโปรเจคไว้ก่อน · รอ BE เพิ่ม `DELETE /api/projects/:id`



---



## 12. ลบประกัน / ลบสัญญา MA (DELETE)



**อยากได้อะไร:** ลบรายการทดสอบประกันและสัญญา MA ได้



**ติดที่หน้าจอไหน:** หน้ารายการการรับประกัน · หน้ารายการสัญญา MA



**ถ้าไม่มีจะเสียอะไร:** กดลบแล้วได้ `Cannot DELETE` เหมือนโปรเจค/ใบปัญหา



**ตอนนี้ (ตรวจ Swagger 13 ก.ย. 2569 ดึก):**  
- `/api/warranties/{id}` = GET, PUT · **ไม่มี DELETE**  
- `/api/ma-contracts/{id}` = GET, PATCH · **ไม่มี DELETE**  
- แผน MA `/api/ma-plans/{id}` มี DELETE แล้ว



**สถานะบนหน้าจอ:** ซ่อนปุ่มลบประกันและลบสัญญา MA ไว้ก่อน

## หมายเหตุเพิ่มเติม — ไม่ถึงขั้นบล็อกงาน แต่ทำให้หน้าจอดีขึ้นมาก



### ก. `GET /api/tasks` ไม่มีตัวกรอง `overdue`

มี `/api/tasks/overdue` แยกต่างหาก ซึ่งใช้ได้ แต่ถ้าเพิ่ม `?overdue=true` ใน `/api/tasks`

จะรวมกับตัวกรองอื่น (`assignedUserId` + `overdue`) ได้ในครั้งเดียว

ตอนนี้หน้าแรกต้องยิง 2 ครั้งแล้วมา intersect ฝั่ง client



### ข. `GET /api/customers` ไม่มี `projectCount`

หน้ารายการลูกค้าอยากโชว์ว่าลูกค้ารายนี้มีกี่โปรเจค

ตอนนี้ต้องยิง `/api/projects?customerId=` ทีละราย — ทำไม่ไหวในหน้ารายการ



### ค. `POST /api/communication-logs` ไม่มีตัวเลือกสร้างงานติดตามต่อ

ปิดงานติดตามแล้วถามว่า "บันทึกการติดต่อเลยไหม" ซึ่งทำได้ด้วย 2 คำสั่ง

ถ้ามี atomic endpoint เดียวจะกันกรณีคำสั่งที่สองพัง
